# Protocols, decision records and historical versions

From the extracted data-and-code archive, run the following offline checks with Python 3.10 or later. They use only the standard library. The first checks the original decision records, and the second command lists every manifest and its original working directory. The separately provided numerical and photometric replays check what the recorded decisions produced.

~~~sh
python commitments/verify_commitments.py
python commitments/verify_commitments.py --details
~~~

The original scientific records contain **52 manifests with 254 digest entries**. Of these, 247 match files at the originally named path and two match independently preserved historical versions. Five refer to private management code or account-usage records described below. A separate check matches the four transmitted hosted handoffs to their source records, checks that the two no-offer cases have empty provenance, and reconstructs 12 learned-model state digests from the archived weight tensors. The archive also contains 33 supporting protocols, specifications and provenance files with copying checksums. The file-level inventory and observed verification results are in [inventory.json](commitments/inventory.json) and [verified.json](commitments/verified.json).

## Paths, chronology and amendments

The inventory records the working directory used for each file of SHA-256 values. For example, run the three small-model checks from records/20261120_scientific_choice_and_recovery, where the original names begin with mechanism/. Run the receiver's registration check from that same round's downstream/ folder. The JSON decision records use paths relative to the round. The unified verifier handles these reference conventions automatically.

Two original commitments name a file that changed later. The earlier menu-free measurement implementation is preserved under [historical/free_workspace_initial/measurements.py](commitments/historical/free_workspace_initial/measurements.py); its digest is 2d047c57ac8d573cf8dd3c11e1abaa816d607d18e1e024202789c478cb14ae34. The original isolated code-write record supplied exactly the 6,590 source bytes, which were checked against the earlier commitment. The final version remains in the scientific run directory. For the frontier forecast, the early science.py is retained as astra/science_initial.py, with digest 150d039e698ff7264008b3e44e10912cde34292b1ce7cabf803a6f80cba44f10. The later science.py, RIDGE_DECISION.md and prediction arrays document the expanded fit. The checker uses the historical versions only for the respective original manifests. The later versions and their results keep their recorded identities.

Five original entries in the frontier manifests concern the authenticated service launcher, its credential-routing helper, the account quota reader, the original result JSON with shared-account usage fields, and the original report mixing scientific data with account-level telemetry. Their recorded digests are retained. The packaging check compared each original to its digest locally, but a recipient cannot verify those five original bytes from this archive. The review copy of the result JSON removes the two administrative fields. Each academic work order, raw scientific reply, decision, saved physical forecast and removal calculation remains available for independent inspection. Reissuing a service request would constitute a new observation. The code that sends authenticated jobs and the unrelated account details are unnecessary for the scientific replay.

The hashes establish byte identity and the dependency relations documented in contemporary local records. Local file dates and the recorded stage sequence do not independently certify when every decision was fixed. These materials are project records rather than an externally timestamped preregistration. The post hoc diagnostic, later interface changes and candidate-specific follow-up remain designated as such in the Article.
