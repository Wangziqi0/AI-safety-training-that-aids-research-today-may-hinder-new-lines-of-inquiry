# Reproducing the analyses

Yifan Chen · Review materials · 21 November 2026

Extract `Data_and_code.zip` into an empty directory. From its top level, run the commands below with Python 3.11 or later. The first command uses the standard library. The second also requires NumPy, SciPy and Astropy and reprocesses the earlier astronomical observations on a CPU. Both analyse recorded outputs offline and write temporary files outside the archive.

```sh
python3 verify_evidence.py
python3 -m venv review-env
. review-env/bin/activate
python -m pip install numpy scipy astropy matplotlib
python verify_evidence.py --prior
```

The summary is JSON. `verified` should be `true`. In the current experiment the check should find 72 Qwen3-8B turns, six distinct fitted-model identities across three paired seeds, 12 primary hosted readers and six secondary readers. First-turn replies included the restricted synthetic label in five of 12 A histories and none of 12 H histories. Every primary reader supplied a valid sharp result for its docket. All six secondary readers reached their respective registered full decision. There were zero linked events in four assigned primary pairs and zero pairs eligible for the conditional loss comparison. The exact mathematical checks reconstruct 729 finite-grid controls and 1,941 interval families. The two arithmetic examples agree on the failed envelope certificate and differ on the underlying budget. Formal compiler receipts document 16 axiom audits and five direct proof-value references. The default numerical check reads those receipts. It does not invoke Lean.

For the earlier results alone, extract `previous/Data_and_code.zip` into another working directory. In that directory, `python verify.py` checks the older figures and previously reported comparisons, `python refit_ordinary.py` independently fits the ordinary astronomical analysis, and `python commitments/verify_commitments.py` reports which original input commitments can be checked. Expect 36 shared calibration projects, ordinary reconstruction for 72 field assignments in each implementation, 404 reversals among 814 initially ordered project pairs and the feasible 8–14 range in the 20-project direction-identification example.

The separate `Optional_trained_adapters.zip` contains the 15 earlier 1.5B and nine 8B learned parameter updates. For weight-based reuse, extract it over the unpacked earlier archive and obtain the public parent weights and model dependencies listed in `previous/Data_and_code.zip` under `PUBLIC_SOURCES.md`. The present proof dockets used the A and H 8B checkpoints for seeds 311, 617 and 929 under base revision `b968826d9c46dd6066d109eabc6255188de91218`. All 72 saved replies identify the checkpoint used. Reissuing the 18 hosted packets would create new observations. Hosted model weights are unavailable from the provider.

For a fresh formal check, obtain Lean 4.33.1 (commit `819816b2e0a3bf405af45ae5c7af2491d8f5bee6`), the upstream project release (SHA-256 `9631b4f020199e580ba86178cb56c6e9b09f690c2369a80dc4334aa93f49c7fc`) and its pinned Mathlib revision `0df444a360eaa60ab8c11dca51a86af692955474`. Build the required upstream imports using that release and its Lake manifest. Point `HANDOFF_LEAN` to its `lean`, `HANDOFF_PROJECT_LIB` to the directory of compiled upstream project modules and `HANDOFF_PACKAGES` to the upstream `.lake/packages` directory. Then run `python study/math/lean_check.py`. The paper's check re-elaborated five published sources whose compiled modules differed from the reference binaries, using the five source hashes in `study/math/source-replay-inputs.json`. All four new study modules type-checked against the resulting dependencies. The original binary differences persist and their cause is undetermined. The archive contains the source URLs and proof-check results. A full upstream project and toolchain are obtained separately.
